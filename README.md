# CNC 가공일정 수립

800대 규모 CNC 가공현장의 일정을 **품목별 수기 입력 없이 한 번에 가배정**하는 도구입니다.
기존 엑셀 통합문서(`CNC 생산계획 자동화` v629 / 매크로 v666)의 시트와 판정 규칙을 그대로 읽어 쓰므로,
마스터 관리 방식은 바꾸지 않고 **"품목 하나씩 호기추천 → 확정 → 다음 품목" 반복만 없앱니다.**

- 설치 없음: `dist/CNC_일정수립.html` 파일 하나를 크롬/엣지에서 열면 됩니다 (인터넷 없이 동작, 글꼴만 기본 글꼴로 대체).
- 데이터는 PC 밖으로 나가지 않습니다. 파일은 브라우저 안에서만 읽고 계산합니다.
- 원본 통합문서는 수정하지 않습니다. 결과는 별도 엑셀 또는 복사/붙여넣기로 옮깁니다.

## 하루 사용 순서

| 순서 | 할 일 | 화면 |
|---|---|---|
| 1 | 일정관리 프로그램 발주를 통합문서 `1_원본붙여넣기`에 붙여넣고 저장 → **[엑셀 불러오기]** 로 .xlsm 선택 (끌어다 놓기 가능) | 상단 |
| 1′ | 또는 통합문서는 그대로 두고 **[원본 붙여넣기]** 에 일정관리 프로그램 복사분(헤더 포함)을 바로 붙여넣기 | 상단 |
| 2 | **[자동 일정수립]** – 미배정·추가배정 전 품목을 납기순으로 가배정 (2,500여 품목 기준 약 3~4초) | 상단 |
| 3 | **간트차트** 에서 결과 확인, 막대를 눌러 호기 변경 / **수기검토** 탭에서 자동기준 밖 품목 처리 | 탭 |
| 4 | **[결과 엑셀 내보내기]** → `9번확정_붙여넣기` 행을 통합문서 `9_설비배정_확정` 마지막 행 아래에 붙여넣기, `프로그램입력요약`(설비1~설비A)으로 일정관리 프로그램 입력 | 상단 |

9번 시트에 붙여넣은 뒤에는 기존 매크로(`CNC_Refresh_Gantt`)로 통합문서 간트/가용일을 갱신하면 됩니다.
다음 날 다시 불러오면 9번 확정분은 "확정"으로, 새 발주만 가배정 대상으로 잡힙니다.

## 자동 일정수립 규칙

기존 매크로의 판정을 그대로 사용합니다. 실제 통합문서(2,739행)로 검증한 결과
`7_배정대상`의 대분류·세부분류·생산성분류·기준일생산량·필요장비일수·권장장비대수·상태가 **전 행 일치**했습니다.

1. **품목 분류** – `5_생산성분류` 우선순위 순 첫 일치 규칙(포함/앞2자리/끝일치/본체끝문자), 대분류는 부품코드 앞 2자리
2. **필요 장비일수** – `올림(발주량 ÷ 기준_일생산량) + 여유일(Y=1일)`, 권장대수 1 / 2 / 2~3 / 3~5 / 수동검토(40일 초과)
3. **후보 호기** – `3_방마스터`(허용대분류·기본소재계열·우선생산성분류·특수방), `4_설비마스터`(일정표기대상·신규셋팅가능·PL/TE/BD가공가능·BD 외경/길이), U품목은 P033 전용, `21_BD규격마스터`
4. **등급** – A(방 점수 150 이상 또는 소재계열 일치+현재소재 일치) / B-2차후보 / C-조건부(도면확인, 자동선택 안 함), 작업상태로 A-즉시·A-예약·A-일정주의 구분
5. **가용일** – `9_설비배정_확정` 구간을 피해 필요한 일수가 연속으로 들어가는 첫 빈 구간. 누적실적 ≥ 계획수량이면 최근실적일 다음날 해제, 완료일이 지났는데 미완료면 **완료확인 필요**(신규배정 제외)
6. **배분** – 여러 대면 가장 먼저 끝나는 호기에 하루씩 배분, 수량은 100개 단위 비례배분(잔여는 가장 긴 호기)

일괄배정에서 추가된 부분:

- **처리 순서**: 특별관리 Y → 요청일 빠른 순 → 장비일수 큰 순. 앞 품목의 가배정이 뒤 품목의 가용일에 바로 반영됩니다.
- **배정 방식 – 분산형(기본, 현장방식)**: 수량이 많아도 가능한 호기를 한꺼번에 쓰지 않고, **가공기간을 요청일까지 늘려 적은 호기**로 편성합니다.
  - 목표 가공기간 = 요청일까지 남은 일수를 `최소 가공기간(7일)` ~ `최대 가공기간(30일)` 범위로 맞춘 값, 호기 수 = 올림(장비일수 ÷ 목표기간), 최대 6대
  - 요청일이 최소 가공기간 이상 남았는데 늦어질 때만 한 대씩 늘립니다. 이미 요청일이 지난 품목에 호기를 몰아넣지 않습니다.
  - **조 분산**: 한 품목은 한 조에 1대까지만 넣고 다른 조의 가능한 호기로 나눕니다 (조가 모자라면 한도를 늘려 보충).
  - **조별 하루 신규셋팅 한도(기본 2건)**: 같은 조에서 같은 날 시작하는 신규 셋팅이 한도를 넘으면 다음 날로 미룹니다. 같은 부품을 바로 이어 가공하는 경우는 신규셋팅으로 세지 않습니다.
  - **조 구성 기준**: ① 4_설비마스터 또는 13_작업자운영마스터의 `조` 열 → ② 담당작업자(한 작업자가 여러 호기를 맡을 때) → ③ 방별 호기번호 순 10대 묶음. 실제 조 편성과 다르면 4_설비마스터에 `조` 열을 추가하세요.
- **배정 방식 – 집중형**: 이전 방식(권장대수 1/2/2~3/3~5로 최단 완료). [기준 설정]에서 고를 수 있습니다.
- **호기 선택**: C-조건부·일정주의·완료확인 필요를 뺀 A/B 후보 중 **먼저 비는 호기** 우선. B후보는 기본 2일 늦게 비는 것으로 보고 A를 우선하며, 같은 부품·같은 재질을 바로 이어 가공하는 호기는 1일 우대합니다.
- **작업자운영**: `13_작업자운영마스터` 상태구분에 "고장"과 시작·종료일이 있으면 그 기간은 배정하지 않습니다. 그 밖의 상태(연차/교육)와 신규세팅금지는 기존처럼 점수 감점과 비고로만 표시합니다.

실제 통합문서(9/28 기준) 비교: 집중형은 한 품목 최대 10대·같은 조 중복 119품목·조별 하루 신규셋팅 최대 14건,
분산형은 한 품목 최대 6대·같은 조 중복 0품목·조별 하루 신규셋팅 최대 2건 (가배정 1,522건, 납기초과 14건은 동일 – 모두 요청일이 이미 지난 품목).

### 기존 매크로와 다르게 처리한 것

- **5번방 소재계열**: 방마스터 5번방 기본소재계열이 `TK/H3J` 인데 매크로는 문자열 완전일치로 비교해 TK 품목과 연결되지 않았습니다(5번방 97대가 추천에서 빠짐). 이 도구는 `/` 로 나눈 항목 중 하나만 맞으면 일치로 봅니다.
- **완료 판정**: 사용안내(0번 시트) 기준대로 "누적실적 ≥ 계획수량 + 최근실적일"이면 완료로 봅니다. 실적확인=Y까지 요구하려면 [기준 설정]에서 바꿀 수 있습니다.
- 품목별 CT/실적 기반 가점(v544/v553)은 아직 반영하지 않았습니다. 확정이력 가점과 연속가공 우선은 반영했습니다.

## 수기검토로 남는 품목과 해결 방법

| 사유 | 해결 |
|---|---|
| BG 전용품 | 품목을 열어 BG 전용호기 번호와 장비일수를 직접 입력 |
| BD규격 미등록/중복 | `21_BD규격마스터`에 부품명·BD외경·BD길이 등록 (기준 점검 탭에서 목록 복사) |
| 재질계열 매핑 없음 | [기준 설정] → 추가 소재계열 매핑 (예: `H5J=TK`) 또는 3_방마스터 보완 |
| 대분류 IS/ST/HD/기타 | 자동추천 규칙 없음 → 호기 직접 입력 |
| 생산성기준 미등록 | `6_생산성기준`에 품목군·기준_일생산량 추가 |
| 완료확인 필요 호기만 남음 | `9_설비배정_확정`의 최근실적일·누적실적 입력 |

## 화면

- **품목 목록**: 상태(미배정/가배정/가배정(지연)/수기검토/배정완료…), 가배정 호기와 기간, 판정 사유. 행을 누르면 상세.
- **간트차트**: 방별 호기 행. 막대에 **부품코드**를 표시하고 **같은 부품은 같은 색**(일정이 가까운 부품끼리는 서로 다른 색). 확정=실선, 가배정=빗금+점선 테두리, 요청일 초과=빨간 테두리, 고장=회색 빗금, 완료확인 필요=빨간 점선. 막대에 마우스를 올리면 같은 부품의 다른 호기 막대가 함께 강조되고, 누르면 품목 상세.
- **품목 상세**: 후보 호기표(등급·조·현재소재·작업상태·가용구간·점수·비고, 20_가능호기조회와 같은 항목, 분산형 기준으로 미리 선택), 체크하거나 `527/528` 형식으로 입력 → [배분 미리보기] → [선택호기 가배정].
- **기준 점검**: 조 구성과 조별 하루 최대 신규셋팅, 방별 부하와 최종완료일, 소재계열 미매핑 재질, 생산성기준 미등록 분류, 완료확인 필요 호기, BD규격 미등록 부품.

가배정은 같은 브라우저에 자동 저장되어 같은 파일 이름을 다시 불러오면 복원됩니다.

## 개발

```
npm install        # 테스트용 SheetJS
npm test           # 엔진/통합문서 입출력 테스트 (node:test)
npm run build      # src/* + vendor/xlsx.full.min.js → dist/CNC_일정수립.html
```

| 파일 | 역할 |
|---|---|
| `src/engine.js` | 분류·장비일수·방/설비 판정·타임라인·후보 정렬·배분·일괄배정 (브라우저/Node 공용) |
| `src/workbook.js` | 통합문서 시트 읽기(시트·헤더 이름 기준), 붙여넣기 텍스트 해석, 결과 엑셀 생성 |
| `src/app.js`, `src/app.css`, `src/index.html` | 화면 |
| `src/demo.js` | 첫 화면·테스트용 가상 데이터 (회사 데이터 아님) |
| `vendor/xlsx.full.min.js` | SheetJS Community Edition 0.18.5 (Apache-2.0, `vendor/xlsx.LICENSE`) |

회사 통합문서(.xlsm)는 저장소에 올리지 않습니다 (`.gitignore`).
